Apache Guacamole Remote Access Gateway

Building a secure, clientless web-based remote access gateway for RDP, SSH, and VNC — no client installation required on the user side.

Project Name: Secure Remote Access Gateway
Author: Asep Nurdin
Role: Infrastructure Engineer
Version: 1.0

01. Project Overview

Modernizing remote access from traditional solutions (VPN + RDP client) to a centralized web-based gateway with complete audit trails.

The Challenge

IT teams and vendors accessing servers via scattered VPN + RDP clients, lacking audit trails, difficult to manage, and prone to credential sharing.

The Solution

Apache Guacamole as a centralized gateway with session recording, native database authentication, and SSL reverse proxy.

The Result

Zero client installation, full audit trail, centralized connection management, and elimination of VPN requirements for basic remote access.

06. Key Features Implemented

Main features implemented to meet enterprise requirements.

  • Clientless Access

    Users only need a modern browser (Chrome, Firefox, Edge) without installing additional applications.

  • Native Database Authentication

    Centralized user management in MySQL database with strong password policy.

  • Session Recording

    Record all RDP/VNC sessions in video format for audit and forensic purposes.

  • Connection Grouping

    Organize connections by team, environment (prod/dev), or business function.

  • Granular Permissions

    Role-based access control: admin, user, and custom permissions per connection.

  • Clipboard & File Transfer

    Secure clipboard sharing and file transfer between client and remote host (can be disabled per policy).

  • Shared Connections

    Multiple users can collaborate in a single remote session (collaborative support session).

  • Connection History

    Complete log of who accessed what, when, and for how long — integrated with session recording.

07. Architecture Overview

Connection flow from end-user to target server through the gateway.

Nginx Reverse Proxy Configuration

server {
    listen 443 ssl http2;
    server_name guacamole.company.com;

    ssl_certificate     /etc/letsencrypt/live/guacamole.company.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/guacamole.company.com/privkey.pem;

    # WebSocket support (required for Guacamole)
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_buffering off;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

08. Security Hardening

Hardening steps applied because Guacamole is a critical attack surface.

HTTPS Only

Disable HTTP, redirect all traffic to HTTPS with HSTS header.

IP Whitelisting

Guacamole access only from office IP ranges and corporate VPN.

Fail2ban

Auto-ban IP after 5 failed login attempts within 10 minutes.

Session Timeout

Auto-logout after 15 minutes of idle time.

Disable Default User

Remove/change default guacadmin account immediately after setup.

Complex Password Policy

Minimum 12 characters, combination of letters/numbers/special chars.

Audit Log

All login and access activities recorded in MySQL database.

Disable Clipboard/File Transfer

For connections to critical production servers.

Regular Security Patching

Update Guacamole & Tomcat regularly to patch vulnerabilities.

MySQL Backup

Daily database backup containing connection & user configurations.

10. Lessons Learned

  • WebSocket Support is Critical

    WebSocket support in reverse proxy is critical — without it, Guacamole won't function.

  • Storage Management

    Session recording consumes significant storage; requires clear retention policy (e.g., 30 days) and logrotate.

  • Authentication Scaling

    Native database authentication is sufficient for small-to-medium scale, but large enterprises should consider LDAP/AD integration.

  • User Adoption

    User adoption requires good training; many initially resist because they're accustomed to RDP clients.

  • Fail2ban Configuration

    Fail2ban is very effective at preventing brute force attacks, but needs internal IP whitelisting to avoid self-lockout.

  • Database Backup

    MySQL database backup must be automated daily — it contains all connection & user configurations.

  • Performance Tuning

    Tomcat performance tuning (max threads, connection pool) is important when users exceed 50 concurrent.

  • Connection Mapping

    Connection mapping documentation (who accesses what) is very helpful during troubleshooting.
