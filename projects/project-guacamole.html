Apache Guacamole Remote Access Gateway

Internet-facing clientless gateway for external vendor access — secure RDP/SSH/VNC without VPN, accessible from anywhere via web browser.

Project Name: External Vendor Access Gateway
Author: Asep Nurdin
Role: Infrastructure Engineer
Version: 1.0

01. Project Overview

Deployed internet-facing Apache Guacamole in DMZ to provide secure remote access for external vendors and third-party support teams — eliminating VPN requirements while maintaining strict security controls.

The Challenge

External vendors and support teams requiring VPN access for server maintenance and troubleshooting. VPN setup was complex, time-consuming (2-3 hours per vendor), difficult to audit, and posed security risks with credential sharing.

The Solution

Internet-facing Apache Guacamole deployed in DMZ with strict security hardening, providing browser-based access without VPN. Vendors can access designated servers via HTTPS from anywhere using only a web browser.

The Result

Zero VPN dependencies, 95% reduction in vendor onboarding time (from 2-3 hours to 5 minutes), complete session audit trails, and granular access control for external parties.

07. Architecture Overview

Internet-facing deployment in DMZ with multiple security layers.

Security Layers

  • Layer 1: Perimeter Firewall

    Only HTTPS (443) allowed from whitelisted vendor IPs, all other traffic blocked.

  • Layer 2: DMZ Isolation

    Guacamole deployed in DMZ network segment, isolated from internal corporate network.

  • Layer 3: Application Security

    SSL/TLS encryption, Fail2ban brute-force protection, session timeout (15 min idle).

  • Layer 4: Access Control

    Per-vendor permissions, specific server access only, no network discovery.

Nginx Reverse Proxy Configuration

server {
    listen 443 ssl http2;
    server_name guacamole.company.com;

    # SSL Configuration
    ssl_certificate     /etc/letsencrypt/live/guacamole.company.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/guacamole.company.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    
    # Security Headers
    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Frame-Options "DENY" always;
    add_header X-Content-Type-Options "nosniff" always;

    # IP Whitelisting (Vendor IPs only)
    allow 203.0.113.0/24;    # Vendor A
    allow 198.51.100.0/24;   # Vendor B
    deny all;

    # WebSocket support (required for Guacamole)
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_buffering off;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

08. Security Hardening

Critical hardening measures because Guacamole is internet-facing and accessible from public networks.

HTTPS Only with HSTS

HTTP disabled,强制 HTTPS redirect with HTTP Strict Transport Security header.

IP Whitelisting

Access restricted to known vendor IP addresses only via Nginx allow/deny rules.

Fail2ban Protection

Auto-ban IP after 5 failed login attempts within 10 minutes to prevent brute-force attacks.

Session Timeout

Automatic logout after 15 minutes of idle time to prevent unauthorized access.

Remove Default Accounts

Default guacadmin account deleted immediately after setup.

Strong Password Policy

Minimum 12 characters with complexity requirements (letters/numbers/special chars).

DMZ Network Isolation

Guacamole server in DMZ, no direct access to internal corporate network.

Disable File Transfer

Clipboard and file transfer disabled for production server connections.

Session Recording

All vendor sessions recorded and stored with 30-day retention policy.

Regular Security Patching

Monthly security updates for Guacamole, Tomcat, and Ubuntu OS.

10. Lessons Learned

  • IP Whitelisting is Critical

    For internet-facing deployments, IP whitelisting at Nginx level is essential — don't rely only on application-level authentication.

  • DMZ Isolation is Non-Negotiable

    Never deploy internet-facing Guacamole directly on internal network — always use DMZ with strict firewall rules.

  • Vendor Training is Essential

    Vendors initially resist browser-based access; hands-on training and clear documentation significantly improves adoption.

  • Session Storage Planning

    Session recordings consume significant storage; plan for 30-day retention with automated cleanup (logrotate).

  • Fail2ban Prevents Attacks

    Internet-facing services are constantly scanned; Fail2ban is essential to auto-block brute-force attempts.

  • WebSocket Configuration is Critical

    Without proper WebSocket support in Nginx, Guacamole connections will fail — test thoroughly before production.

  • Per-Vendor Access Mapping

    Document which vendor has access to which servers — crucial for audit and troubleshooting.

  • Regular Security Audits

    Quarterly review of vendor accounts, IP whitelist, and access logs to remove inactive vendors and detect anomalies.
