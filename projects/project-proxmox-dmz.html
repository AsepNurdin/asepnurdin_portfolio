DMZ Virtualization with Proxmox VE

Setup baru single-node Proxmox VE untuk virtualisasi DMZ server dengan fokus pada security isolation dan resource optimization. Implementasi dari awal untuk 4 workload DMZ kritis dengan security hardening.

Project Name: DMZ Virtualization
Author: Asep Nurdin
Role: Infrastructure Engineer
Version: 1.0

01. Project Overview

Implementasi baru platform virtualisasi DMZ menggunakan single-node Proxmox VE untuk men-hosting 4 aplikasi kritis perusahaan. Proyek ini dibangun dari awal dengan fokus pada security isolation, resource optimization, dan centralized management.

The Challenge

Perusahaan membutuhkan infrastruktur DMZ yang aman dan terisolasi untuk men-hosting aplikasi kritis (HRIS, PPS, Nextcloud, Guacamole) dengan requirement security yang ketat, resource allocation yang terukur, dan centralized management yang mudah di-maintain.

The Solution

Single-node Proxmox VE dengan network segmentation ketat, firewall rules, dan resource allocation per-VM untuk workload DMZ. Pendekatan ini memungkinkan konsolidasi resource, centralized management, dan implementasi security policy yang konsisten di seluruh workload.

The Result

Infrastruktur DMZ yang aman, terisolasi, dan teroptimasi untuk 4 workload kritis. Semua aplikasi berjalan di platform terpadu dengan monitoring terpusat, backup otomatis, dan security posture yang kuat.

04. DMZ Workloads

4 aplikasi kritis yang di-deploy di DMZ dengan resource allocation spesifik.

  • HRIS (Human Resource Information System)

    Sistem manajemen data karyawan, absensi, dan payroll yang memerlukan akses dari berbagai lokasi. Resource: 4 vCPU, 8GB RAM, 100GB SSD | OS: Ubuntu 22.04 LTS | Access: Web-based, HTTPS only

  • PPS (Performance & Payroll System)

    Sistem penilaian kinerja dan pengolahan gaji terintegrasi dengan data HRIS. Resource: 4 vCPU, 8GB RAM, 100GB SSD | OS: Ubuntu 22.04 LTS | Access: Internal network only

  • Nextcloud

    Platform file sharing dan kolaborasi internal sebagai pengganti cloud publik. Resource: 4 vCPU, 8GB RAM, 500GB Storage | OS: Ubuntu 22.04 LTS | Access: Web + Mobile clients

  • Apache Guacamole

    Gateway remote access untuk RDP/SSH/VNC tanpa perlu client installation. Resource: 2 vCPU, 4GB RAM, 50GB SSD | OS: Ubuntu 22.04 LTS | Access: Web-based, 2FA enabled

05. Security Implementation

Hardening measures untuk memastikan DMZ isolation dan protection.

Network Segmentation

Pemisahan strict antara DMZ network dan internal network menggunakan VLAN dan firewall rules.

Proxmox Firewall

Firewall diaktifkan di level Datacenter dan per-VM dengan whitelisting approach.

2FA Authentication

Wajib Two-Factor Authentication untuk akses Guacamole dan Proxmox GUI.

SSL/TLS Encryption

Semua akses web menggunakan HTTPS dengan certificate yang valid.

Audit Logging

Centralized logging untuk semua akses dan aktivitas di DMZ server.

Automated Backup

Daily backup dengan retention policy dan encrypted storage.

06. Architecture Highlights

Desain arsitektur yang mengutamakan security dan resource efficiency.

Key Design Decisions

  • Single Node

    Cukup untuk workload DMZ, mengurangi kompleksitas dan cost operasional.

  • Dedicated DMZ VLAN

    Isolasi penuh dari internal network untuk mencegah lateral movement.

  • Resource Reservation

    CPU dan RAM di-reserve per VM untuk performance guarantee dan mencegah noisy neighbor.

  • ZFS Storage

    Data integrity dan snapshot capability untuk backup yang reliable.

  • Bridge Network

    Linux bridge untuk flexibility dan VLAN tagging yang mudah di-manage.

08. Lessons Learned

  • Network Isolation is Key

    Network isolation adalah kunci security DMZ — jangan pernah kompromi pada segmentation.

  • Resource Reservation Matters

    Resource reservation penting untuk mencegah "noisy neighbor" antar VM di single node.

  • Guacamole Requires Hardening

    Guacamole sangat powerful tapi harus di-hardening dengan 2FA dan IP whitelisting.

  • Backup Testing is Critical

    Backup testing sama pentingnya dengan backup itu sendiri — restore test secara berkala.

  • Documentation Prevents Security Debt

    Dokumentasi firewall rules wajib di-update setiap ada perubahan agar tidak jadi "security debt".

  • Monitoring is Essential

    Monitoring resource usage sangat kritikal di single-node untuk anticipate bottleneck.
