01. Project Overview

Implementing robust network security through FortiGate 200F NGFW with granular policy control, hardware-accelerated inspection, and traffic segmentation.

The Challenge

Uncontrolled traffic flow between internal network, DMZ servers, and internet with minimal visibility, no centralized policy management, and high risk of lateral movement.

The Solution

FortiGate 200F deployment with zone-based architecture, comprehensive security policies, NAT configuration, and content security profiles leveraging SP5 processor acceleration.

The Result

Complete traffic visibility, reduced attack surface by 70%, centralized policy management, and compliance with security best practices — all with hardware-accelerated throughput.

03. Security Zone Architecture

Three-tier security zone design with strict traffic control between zones, mapped to FortiGate 200F physical interfaces.

Internal Network

Trusted corporate network with workstations, internal servers, and business applications. Connected to FortiGate via internal switch. High Trust

DMZ (Demilitarized Zone)

Semi-trusted zone hosting public-facing services: HRIS, PPS, Nextcloud, and Guacamole gateway servers. Medium Trust

External / Internet

Untrusted external network connected via ISP. All traffic from this zone is treated as potentially malicious. Untrusted

09. Key Features Implemented

Core firewall capabilities configured for comprehensive security on FortiGate 200F.

  • Zone-Based Architecture

    Clear separation of Internal, DMZ, and External zones with strict inter-zone policies.

  • Source NAT (SNAT)

    Internal users access internet through masquerading NAT using public IP pool.

  • Destination NAT (DNAT/VIP)

    External users access DMZ services via Virtual IP mapping to internal server IPs.

  • Hardware-Accelerated IPS

    SP5 processor accelerates intrusion prevention for high throughput without performance loss.

  • Antivirus Scanning

    File-level malware detection for HTTP, FTP, SMTP, and POP3/IMAP traffic.

  • Web Filtering

    Category-based web access control powered by FortiGuard to block malicious sites.

  • Application Control

    Identify and control applications regardless of port or protocol (e.g., block P2P).

  • SSL Inspection

    Deep packet inspection of encrypted HTTPS traffic to detect hidden threats.

  • DNS Filtering

    Block DNS resolution to known malicious domains via FortiGuard DNS threat feed.

  • Comprehensive Logging

    All traffic logged with detailed information for audit, troubleshooting, and forensics.

10. Network Architecture

Traffic flow through FortiGate 200F with zone-based security enforcement.

Example FortiGate 200F CLI Configuration

# Example FortiGate 200F CLI configuration for security policy

config system interface
    edit "port1"
        set ip xx.xx.xx.xx xx.xxx.xxx.x
        set alias "Internal"
    next
    edit "port9"
        set ip xx.xx.xx.xx xx.xx.xx.x
        set alias "DMZ"
    next
end

config firewall vip
    edit "DMZ-Web-VIP"
        set extip <public-ip>
        set extintf "port13"
        set mappedip "172.16.10.10"
        set portforward enable
        set extport 443
        set mappedport 443
    next
end

config firewall policy
    edit 1
        set name "Internal to Internet"
        set srcintf "port1"
        set dstintf "port13"
        set srcaddr "all"
        set dstaddr "all"
        set action accept
        set service "HTTP" "HTTPS" "DNS"
        set logtraffic all
        set utm-status enable
        set av-profile "default"
        set webfilter-profile "default"
        set ips-sensor "default"
    next
    edit 2
        set name "Internet to DMZ Web"
        set srcintf "port13"
        set dstintf "port9"
        set srcaddr "all"
        set dstaddr "DMZ-Web-VIP"
        set action accept
        set service "HTTPS"
        set logtraffic all
        set utm-status enable
        set ips-sensor "high-security"
    next
end

13. Lessons Learned

  • Deny-All Baseline

    Start with a "deny-all" baseline and selectively allow only necessary traffic — this is the foundation of secure firewall design.

  • Policy Naming Convention

    Policy naming convention is critical for long-term maintainability (e.g., "Source-to-Destination-Service").

  • Regular Policy Audit

    Regular policy audit is essential — unused rules accumulate over time and create security gaps.

  • SSL Inspection Performance

    SSL inspection can impact performance; leverage SP5 hardware acceleration and test thoroughly before enabling on high-traffic policies.

  • DMZ Outbound Restrictions

    DMZ servers should have minimal outbound access — only allow what's absolutely necessary (DNS, updates).

  • Log Storage Planning

    Logging everything is important, but log rotation and storage planning must be considered early.

  • Involve Application Owners

    Involve application owners during policy design to understand legitimate traffic patterns.

  • Document the "Why"

    Document the "why" behind each policy, not just the "what" — this helps during future audits and troubleshooting.

  • Interface Planning

    FortiGate 200F's multiple GE ports make interface planning critical — label and document port-to-zone mapping clearly.

  • Failover Procedures

    Even without HA, plan for manual failover procedures and document recovery steps.
