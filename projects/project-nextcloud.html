Nextcloud Self-Hosted Collaboration Platform

Replacing public cloud storage with a secure, self-hosted Nextcloud instance for enterprise file sharing, real-time collaboration, and complete data sovereignty.

Project Name: Enterprise File Collaboration
Author: Asep Nurdin
Role: Infrastructure & Application Engineer
Version: 1.0

01. Project Overview

Migrating from public cloud storage (Google Workspace/Dropbox) to a fully self-hosted Nextcloud Hub deployed in the corporate DMZ, ensuring complete data sovereignty and reducing recurring SaaS costs.

The Challenge

Sensitive corporate documents stored on public cloud services posed data sovereignty risks. Recurring subscription costs were high, and IT had zero control over data residency, compliance, and granular access policies.

The Solution

Nextcloud Hub deployed on a dedicated Proxmox VM (Ubuntu 22.04) with Nginx, PHP-FPM, MariaDB, and Redis. Integrated with Active Directory (LDAP) for Single Sign-On (SSO) and secured with strict hardening policies.

The Result

100% data sovereignty, 60% reduction in annual cloud subscription costs, seamless real-time collaboration via OnlyOffice, and unified identity management via LDAP/AD integration.

05. Architecture Overview

High-performance LEMP stack architecture optimized for Nextcloud.

Nginx Hardening Configuration

server {
    listen 443 ssl http2;
    server_name cloud.company.com;

    # SSL & Security Headers
    ssl_certificate /etc/letsencrypt/live/cloud.company.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/cloud.company.com/privkey.pem;
    add_header Strict-Transport-Security "max-age=15768000; includeSubDomains; preload;" always;
    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Referrer-Policy "no-referrer" always;

    # PHP-FPM Configuration
    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.1-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
        fastcgi_buffers 64 4K;
        fastcgi_busy_buffers_size 128k;
    }
}

06. Performance Tuning

Critical optimizations applied to handle 100+ concurrent users smoothly.

PHP OPcache & APCu

Enabled OPcache for bytecode caching and APCu for local memory caching to reduce PHP execution time.

Redis Transactional Locking

Configured Redis for file locking and transactional file locking to prevent database bottlenecks.

System Cron Jobs

Switched from AJAX background jobs to System Cron for reliable execution of maintenance tasks.

Nginx Gzip & Brotli

Enabled compression for static assets (CSS, JS, fonts) to reduce bandwidth and improve load times.

07. Security Hardening

Security measures implemented to protect the self-hosted platform.

  • HSTS & SSL/TLS 1.3

    Enforced HTTPS with HTTP Strict Transport Security and modern TLS protocols only.

  • Brute-Force Protection

    Enabled Nextcloud built-in brute-force protection and integrated Fail2ban at the OS level.

  • Encryption at Rest

    Enabled server-side encryption for sensitive folders using OpenSSL keys managed by IT.

  • File Integrity Check

    Regular integrity scans to detect unauthorized modifications to core Nextcloud files.

  • Disabled Public Registration

    Disabled public user registration; all accounts must be provisioned via LDAP/AD sync.

09. Lessons Learned

  • PHP Tuning is Critical

    Default PHP-FPM settings are insufficient for 100+ users. Tuning `pm.max_children` and `memory_limit` is mandatory.

  • Redis for Locking

    Using the database for file locking causes severe bottlenecks. Redis transactional locking is a must for production.

  • System Cron over AJAX

    Background jobs must use System Cron, not AJAX, to ensure reliable execution of maintenance and sync tasks.

  • LDAP Caching

    LDAP queries can be slow. Enable LDAP caching in Nextcloud to reduce authentication latency.

  • Regular Integrity Scans

    Run `occ integrity:check-core` regularly to ensure no core files have been tampered with or corrupted.

  • Backup the Config Directory

    The `config/config.php` file contains encryption keys and DB credentials. Backing it up is as critical as the database itself.
